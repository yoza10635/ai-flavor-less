# StoryScope 对 ai-flavor-less 的进化指导性评估

> 评估对象：arXiv:2604.03136v6（COLM 2026）· 评估日期：2026-09-15
> 被评估方：`Skills/AI-flavor-less`（六层统计型中文 AI 味检测）

---

## 一、结论先行

| 维度 | 充足性 | 说明 |
| --- | --- | --- |
| **方向指导性** | **充足** | 精确划定了现有能力边界、指出更有价值的一层、给出 30 条可翻译成改写动作的画像特征 |
| **实现指导性** | **不充足** | 无直接可移植算法；能纯统计近似的仅 4 条，其中 3 条只在多章聚合下有效 |
| **数值指导性** | **不适用** | 英文 Books3 文学短篇的阈值对中文网文零迁移性，必须靠自有基线校准 |

**一句话**：值得当 **v2 的路标**，不值得当 **v2 的实现蓝图**。

## 一·补、重要修正：不是三层，而是四层（2026-09-15 追加）

初版把"StoryScope 那一层"笼统称为**叙事层**，并据此提出从正文里统计近似叙事特征的 L4 方案。
**这个框架是错的**——叙事层与大纲层不是同一个层级。修正后的层级模型：

| 层 | 载体 | 性质 | 可测性 | 改动成本 |
| --- | --- | --- | --- | --- |
| 设定层 | `01-设定` / `02-势力与人物` | 世界观、势力、人物档案 | 结构化，可测但与"叙事"无关 | — |
| **大纲层** | `03-剧情`（事件块 / 分纲 / 伏笔总台账）、`06-章纲` | **作者规划（plan）** | **结构化 → 纯规则可测** | **极低（改一行章纲）** |
| **叙事层** | `05-正文`中读出来的结构 | **规划的实现结果（realized discourse）** | 需 LLM 语义抽取 | 高（重写正文） |
| 文笔层 | `05-正文`字词句段表面 | 表面纹理 | 纯统计（现有 L0–L3） | 低（词句替换） |

### 三层关系的关键点

1. **大纲层 ≠ 叙事层，且两者值可以不一致。**
   章纲规划了三条支线，成稿可能写成单线；章纲时间线线性，成稿可能大量倒叙。
   同一维度（支线、时间线、POV）在**两层都有**，但是**不同的量**：一个是"打算怎么写"，一个是"实际写成什么"。
   → 因此不能用叙事层的结论去推断大纲层，反之亦然。

2. **两者对"纯统计"的可行性完全相反。**

   | StoryScope 特征 | 叙事层（从正文） | 大纲层（从章纲） |
   | --- | --- | --- |
   | 支线数量 / 单线情节 | ❌ 需人物-事件图 | ✅ 表列/字段计数 |
   | 地点跨度 Location Variety | ❌ 需语义识别 | ✅「场景」列 |
   | POV 配比 Perspective | ❌ 需 LLM 判定聚焦 | ✅ 显式百分比字段 |
   | 事件升级曲线 | ❌ 需事件图 | ✅「情绪」列的节拍幅度 |
   | 伏笔跨度与回收率 | ❌ 全书语义匹配（O(n²)） | ✅ 台账的有向图 |
   | 因果链连续性 | ❌ 需因果推断 | ✅「核心事件」的 → 链条长度 |
   | 道德模糊主角 | ❌ 需价值判断 | ❌ 同样做不到 |

   > **反直觉但关键：StoryScope "纯统计做不到"的那些特征，在大纲层的结构化字段里反而全部可测。**

3. **修正后的结论：上一轮的 L4 方案（从正文统计近似叙事特征）是次优解。**
   它同时踩了两个坑——难做（只能近似 4 条）+ 难改（要重写正文）。
   更优的杠杆在**大纲层**：纯规则可测、改动成本极低、不破坏 skill 定位。

### 已验证的前提（实测）

对 `Project/novel-create` 抽取 10 个章纲文件做字段覆盖统计：

```
节拍表=1  POV=1  伏笔操作=1  钩子=1  剧情要点=1  表行=3   → 10/10 文件完全一致
```

章纲实际字段：`所属事件块` / `所在卷` / `POV`（显式百分比）/ `预计字数` / `章节定位` /
`场景节拍表`（# / 场景 / 出场人物 / 情绪 / 字数占比）/ `剧情要点`（核心事件 / 次要事件 / 角色成长）/
`伏笔操作`（预埋 / 持续 / 回收 + 伏笔 ID）/ `钩子`

`03-剧情/03-伏笔/伏笔总台账.md`（322 行）为结构化表：
`伏笔ID | 内容 | 预埋事件 | 回收事件 | 状态` → 天然是一张**有向图**，可算跨度、并发数、回收率、超期未回收。

→ **规则化抽取 100% 可行，无需 LLM。**

### 战略含义：预防 vs 事后

> **叙事层 AI 味的成因在大纲层。** 章纲规划成"单线顺叙、单一 POV、每章点题"，成稿必然带叙事 AI 味——这是**规划决定**的，不是文笔决定的。

所以在**大纲层**检测是**预防**（写之前就拦住），在**正文**检测是**事后**（写完只能重写）。
对"去 AI 味"这个用户目标，预防的杠杆远大于事后。

## 一·补2、再修正：大纲层不是"叙事层 AI 味的总开关"（2026-09-15 实测）

§一·补 里写的"**叙事层 AI 味的成因在大纲层**"**说过头了**。按 30 个核心特征逐条拆分，大纲层的可控性是三档而非全控：

| 档 | 数量 | 特征（示例） | 机制 |
| --- | --- | --- | --- |
| **强控制** | 约 8 条 | 支线数量 / 单线情节、地点跨度、时间线形态、伏笔跨度、道德模糊主角、结局能动性归属 | 信息论约束：章纲没规划，成稿写不出来 → **大纲层是必要条件** |
| **半控制** | 约 8 条 | 因果链连续性、揭示改写前文、对白占比、互文具名度、结局性质、场景空间粒度 | 大纲提供条件，实现程度靠写作层 |
| **呈现类** | 约 14 条 | 叙述者显式点题（77% vs 52%）、身体化写情绪（38% vs 81%）、感官密度、内心描写深度、破第四面墙 | **LLM 的采样倾向**，与规划无关 |

**为什么大纲层不充分**：结构类受**信息论**约束（无中生有很难），呈现类受**采样分布**约束（不管章纲怎么写，模型都会倾向把叙述者当主题解说员、用身体/物件写情绪、给象征性收尾）。两者机制不同，不能用同一个杠杆解决。

### 修正：呈现类并非"完全管不到"，而是只能通过「钩子」字段间接影响

实测发现，章纲的 `### 钩子` 字段是一段**散文种子**（不是结构化字段）。ch076 章纲钩子写的是：

> 他合上本子。院子里的枣树影子歪在西墙上。萧嫣的丹炉在响。叶瑶的算盘在响。两种声音混在一起。他喝了口茶。茶凉了。

正文完全照做并**加强**了（"枣树上一颗果子掉下来。红的。熟透了。滚到井台边。陈序没捡。"）。

→ 所以呈现类的**有无**可以被钩子字段引导，但**密度/程度**仍由写作层决定。
→ **这是对 C′ 方案的重要补充：钩子字段应当被纳入大纲层检测范围。**

### 实证检验（在 `Project/novel-create` 上实跑）

**前置：修掉一个拦路 bug。** `assets/report_template.md.j2:155` 的 `{% for si, s in r.items %}` 中，`r` 是 dict，
Jinja2 对 `foo.bar` 先 `getattr` 再 `getitem` → `r.items` 解析为 **dict 的 `.items` 方法**，
抛 `TypeError: 'builtin_function_or_method' object is not iterable`。
**只要存在任何重复骨架簇（真实章节必然有），章报告 100% 崩溃。** 已修为 `r['items']`。

修复后实跑 ch072 / ch075 / ch076（网文 profile）结果：

```
章 | 语义句 | 重复骨架簇 | 排比簇 | 平均σ | 平均MSSD | 的密度 | flags
第七十六章 暗流 | 433 | 21 | 0 | 3.8 | 5.3 | 2.3 | 重复骨架×21(18%)；信息停滞×8；词性堆叠×1；节奏偏匀；破折号26.9
第七十五章 节奏 | 307 | 14 | 0 | 2.9 | 3.3 | 1.6 | 重复骨架×14(22%)；词性堆叠×1；节奏偏匀；破折号22.1
第七十二章 师父 | 252 | 14 | 0 | 3.7 | 5.3 | 3.1 | 重复骨架×14(17%)；词性堆叠×1；节奏偏匀；破折号15.0
```

**全部 flags 都落在文笔层**（L0/L1/L2/L3/L0.5），**没有任何一条触到结构类或呈现类**。

### 关键对照：大纲规划没问题，正文照样带呈现类 AI 味

这三章的章纲**结构上是好的**——POV 显式配比（40/35/25）、三场景节拍、伏笔操作带 ID、事件块归属明确。
但正文仍然出现：

| 正文实际写法 | 对应 StoryScope 特征 | 工具是否报出 |
| --- | --- | --- |
| "枣树上一颗果子掉下来。红的。熟透了。滚到井台边。陈序没捡。" | Setting as Psychological Mirror / 物件象征 | ❌ 未报 |
| "东屋的灯亮了。西屋的灯没亮——叶瑶还没回来。" | Environmental Emphasis / 情绪外部化 | ❌ 未报 |
| "两条线。两个徒弟。两个方向。" | Thematic Unity / 排比概括（点题倾向） | ❌ 未报 |
| "太阳落了。…明天——该收枣了。" | 象征性收尾 / Resolution Mode | ❌ 未报 |
| 短句均匀（σ 2.9–3.8） | — | ✅ L3「节奏偏匀」捕捉到 |

→ **落点结论：结构类被大纲层解决了，节奏被 L3 捕捉了，呈现类掉进了缝隙。**

### 意外发现：跨章「收尾装置复用」（最值得做的新指标）

抽取全部 10 个章纲的 `### 钩子` 段比对，发现同一批收尾装置在跨章复用：

| 装置 | 出现章节 | 频次 |
| --- | --- | --- |
| "合上本子 / 写了一行" | ch070、ch072、ch075、ch076 | **4 / 10** |
| "茶"（倒茶 / 喝茶 / 茶凉了） | ch070、ch072、ch075、ch076 | **4 / 10** |
| "灯灭了 / 环境声收尾" | ch067、ch069、ch074、ch075 | **4 / 10** |
| "看了她/他/陈序一眼" | ch071、ch073、ch074（几乎同骨架） | **3 / 10** |
| 极短应答收尾（"嗯。" / "没。"） | ch070、ch071 | 2 / 10 |

**为什么这条重要**：
1. 这正是 StoryScope 意义上"**叙事声音统一 / 事件升级平坦**"的规划层对应物——Claude 被判定为"最统一"的那类特征。
2. 它是**纯词汇锚定**的（"合上本子"四个字就是锚点），**不需要 LLM、不需要语义理解**。
3. **现有 skill 抓不到**：L2 骨架聚类是**章内**的，跨章装置复用完全不可见；汇总表只出计数，不做跨章模式匹配。
4. 它**同时可在大纲层与正文层测量**，而大纲层更便宜（钩子只有几行，正文要几千字）。

→ **建议作为 C′ 的最高优先级指标**：`跨章收尾装置复用率`。

### 修正后的完整结论

| 层 | 解决什么 | 手段 |
| --- | --- | --- |
| 大纲层 | **结构类**（约 8 条，必要条件）+ 通过钩子字段引导**呈现类的有无** | 规则检测 + 钩子字段控制 |
| 生成时 | **呈现类的程度**（身体化密度、点题程度） | prompt / 创作规范约束 |
| 事后（正文） | **叙事模板化**（跨章装置复用） | 纯规则跨章比对 |

**没有任何单层能"解决"叙事层 AI 味。** 大纲层是结构类的必要条件与最小成本干预点，但不是总开关。

## 二、根本原因：两者不在同一技术层，且纵向维度正交

|  | ai-flavor-less | StoryScope |
| --- | --- | --- |
| 纵向维度 | 字 → 词 → 句 → 段 | 篇 → 情节 / 时间 / 人物 / 视角 |
| 所属层 | **文笔层（prose）** | **叙事层（narrative）** |
| 特征来源 | 纯统计（jieba POS、n-gram、句长分布） | LLM 语义标注（Gemini 3 Flash 打 304 个特征） |
| 单篇成本 | ~0（本地 CPU 秒级） | 约 $0.07 / 5000 词，需全文 + API |
| 可复现性 | 确定性数值，同输入同输出 | 依赖第三方模型版本，随模型更新漂移 |
| 输出 | flags + 修改抓手 | 可解释特征 + SHAP 归因 |

**关键判断：现有的六层（L0 / L0.5 / L1 / L1.5 / L2 / L3）全部落在文笔层。** StoryScope 的 304 个特征则全部落在叙事层。二者几乎没有重叠。

论文本身提供了"两层正交"的直接证据：LAMP 框架把表层 AI 痕迹 span-level 改掉之后，叙事检测器仍达 **93.9%**（仅比未改写低 1.6 点）。这意味着——

> **表层痕迹与叙事结构是相互独立的两个信号源。**

反过来读这条结论，就是对本 skill 能力上限的判定。

## 三、论文给出的三条"负面但高价值"的结论

### 结论 1：文笔层是最容易被绕过的一层

- GPT-5.4 已显著减少 em-dash（本 skill 的 `dash_thresh` 正在监测的正是这个信号）
- 微调模仿人类风格可使创意写作检测率从 97% → 3%
- LAMP 式专业改写后，表层检测的收益极其有限

本 skill 的 `dash_thresh`、`tpl_thresh`（20 组模板词对）、`de_density_thresh`（'的'密度）都是**可被下一代模型自然消退**的信号。这不是规则写错了，而是**这类信号本身就有时效性**。

### 结论 2：只在词句层改写，AI 味不会真正消失

论文证明，删掉 cliché、紫色散文、冗余说明之后，AI 文本的**叙事骨架**（主题过曝、因果整齐、单线无支线、时间线性、身体化写情绪）完全没变。

> **这是本 skill 目前最大的产品缺陷**：用户跑完检测，照着 flags 把 '的'链、模板词对、破折号全部改掉，报告会变漂亮，但 AI 味**并没有真正去掉**——只是从"可检测的文笔层"退到了"不可检测的叙事层"。检测器给了一种**虚假的改善感**。

### 结论 3：叙事层更耐久，因为改它需要结构性重写

改叙事决策（加支线、打乱时间线、去掉点题段）需要重写故事结构，而不是替换词句。论文明确以此论证叙事的"持久性"。

> 这条同时给出了**升级方向的合法性**：往叙事层扩展不是锦上添花，而是覆盖了唯一"改起来昂贵"的信号带。

## 四、可落地的增量：按可行性排序

### ✅✅ 首选：L4-大纲（大纲层检测，优先级最高）

**为什么优先**：纯规则可测（不破坏"不靠 LLM"的定位）+ 改动成本极低（改一行章纲）+ 位于成因上游（预防而非事后）。

#### 可算指标（全部来自章纲/事件块/伏笔台账的结构化字段）

| 指标 | 数据来源字段 | 对应 StoryScope 特征 | 判定方向 |
| --- | --- | --- | --- |
| **跨章收尾装置复用率** ← **最高优先级（已实测有效）** | 章纲「钩子」段 / 正文末段 | 叙事声音统一、Claude 式 flat escalation | 同一装置（"合上本子"/"茶"/"灯灭"）跨章复现 ≥3 次 |
| **多线并发度** | 章纲「所属事件块」+ 剧情要点「次要事件」 | Subplot Integration | 次要事件为空 → 单线风险 |
| **POV 集中度** | 章纲「POV」显式百分比 | Perspective / Breadth of focalization | 单 POV 占比过高 = AI 味（论文：人类更多 focalization 切换） |
| **地点跨度** | 场景节拍表「场景」列去重 | Location Variety Scope | 地点重复率高 → 单调 |
| **场景密度** | 场景节拍表行数 / 章 | 事件密度 | 长期恒定 3 场景 = 模板化（注意：本项目当前 10/10 章都是 3 行） |
| **情绪节拍幅度** | 场景节拍表「情绪」列的 `A→B` 箭头 | 事件升级曲线 / Claude 的 flat escalation | 长期"平静→暗流"同向同幅 = 升级平坦 |
| **伏笔并发与跨度** | 伏笔总台账（预埋→回收有向图） | Revelation pacing | 活跃伏笔数、跨度分布、超期未回收 |
| **点题率** | 章纲「钩子」段 | Narratorial Thematic Commentary | 钩子末端出现抽象总结句 → 点题 |
| **章节功能分布** | 章纲「章节定位」 | Plot vs Atmosphere orientation | 日常章/过渡章占比过高 → 无事件推进 |

> **「跨章收尾装置复用率」是本次实测中最有价值的发现**：它对应 StoryScope 的叙事层结论，却是纯词汇锚定的（不需要 LLM），
> 且现有 L2 骨架聚类因"章内作用域"而完全无法捕捉。见 §一·补2 的实测数据。

> 「场景密度」这条已经能给出可操作信号：当前 10 章全部是 **3 行节拍表**，即结构完全同构。这正是"模板化"在规划层的直接体现——而且是子标注式的确定性证据。

#### 建议实现方式
- 新增 `--source=大纲|正文` 参数（默认 `正文`，保持向后兼容），或独立入口 `check_outline.py`。
- 大纲层指标与正文层指标**分开报告**，不要混进同一份 flags 汇总（两层的语义不可比）。
- 阈值同样走 `--calibrate`，但基线应取**已评审通过的章纲批次**，而非正文章节。

### ✅ 可做（叙事层：纯统计可近似）

#### L4-A 时间线复杂度
- **对应特征**：Chronological Discontinuity（人类 2.40 vs AI 2.12）、Anachrony Intensity（2.58 vs 2.31）、Nonlinear Framing（1.96 vs 1.68）
- **统计近似**：中文时间锚点词表（"三年前""当年""十年后""如今""彼时""那一年""上个月"）+ 出现位置序列 → 计算时间戳指向前后的**跳变次数与幅度**；倒叙起始标记（"他想起""许多年前""回忆"）的位置分布
- **可行性依据**：中文时间表达有强词汇锚点，无需语义理解即可抽取
- **⚠️ 限制**：单章 3,000–5,000 字时间跨度太短，**必须在多章/整篇聚合下使用**

#### L4-B 篇末点题检测（可行性最高）
- **对应特征**：Narratorial Thematic Commentary（人类 52% vs AI **77%**）、Thematic Explicitness（3.28 vs 3.94）
- **统计近似**：检测**章末段 / 场景收尾处**的"抽象名词 + 判断动词"句
  - 抽象名词表：命运、人性、意义、救赎、真相、成长、孤独、记忆、尊严、自由、代价、时间
  - 判断动词：是 / 在于 / 就是 / 终究是 / 不过是 / 才是
  - 排除项：句内含具体动作动词、含引号对话
- **优势**：每章都有收尾段，**单章即有效**，是四条里最容易落地的一条

#### L4-C 读者介入 / 元叙述
- **对应特征**：Fourth-Wall Permeability（67% vs 39%）、Direct Reader Address（28% vs **7%**）
- **统计近似**："读者""亲爱的读者""诸位""你"（叙述对象而非对话内）、元叙述标记（"这个故事""说到这里""回头再看""本章"）
- 纯词表 + 位置规则即可，**难度最低**

#### L4-D 互文具名度
- **对应特征**：Intertextual Strategy → explicit named reference（**47% vs 24%**）、Reference Explicitness → implicit echoes（人类 50% vs AI **72%**）
- **统计近似**：《》书名号引用密度、"像……那样"的具名比较、引号内专名 → 计算**具名 vs 泛指**比例
- **⚠️ 限制**：中文类型差异大（玄幻少用《》、都市多用），需按 profile 分别校准

### ⚠️ 需要验证的一条认知冲突（最值得警惕）

**本 skill 的 `EMO_PAT`（情绪直写检测）与论文结论方向相反。**

| 指标 | 人类 | AI | 本 skill 现行 |
| --- | --- | --- | --- |
| 直接情绪标签 | **29%** | 8% | 判为 AI 味 ⚠️ |
| 身体化情绪表达 | 38% | **81%** | 未检测 |

论文实测：在英文文学短篇里，**直写情绪是人类特征，身体化描写才是 AI 特征**。

**但这不一定说明规则错了**——`EMO_PAT` 来自中文网文创作规范，中文网文 AI 输出确实高频直写情绪，这**可能是真实的中英语体/体裁差异**。

**处理方式**：不要用论文覆盖现有规则。这应该作为一个**实证问题**用自有语料验证：
```
取 N 篇已确认 AI 生成的章节 + N 篇人类章节
分别跑 check.py，对比 EMO_PAT 命中率
→ 若 AI 组命中率未显著高于人类组，说明规则与目标语体不匹配
```
这个实验成本极低、信息量极大，应在任何扩展之前做。

### ❌ 不能做（纯统计做不到，别硬塞）

| 特征 | 为什么做不到 |
| --- | --- |
| 支线数量 / 单线情节（79% vs 57% 无支线） | 需要人物-事件图，非文本表面统计可及 |
| 因果链连续性、事件升级曲线 | 同上，需事件图与因果推断 |
| 人物能动性（结局由主角选择驱动 69% vs 46%） | 需要判定"结局的成因归属"，是语义判断 |
| 道德模糊主角（59% vs 38%） | 需要价值判断 |
| 叙事空间稀有度（0.71 vs 0.49） | 需要一个 304 维语义空间作参照系，纯统计无法构造 |

## 五、架构建议：不破坏现有定位

### 硬约束
本 skill 的核心卖点是"**不靠 LLM 判断，用可复现的数值指纹**"。**这条不能破。**
→ **不要引入 LLM 标注**。StoryScope 的 304 特征全部依赖 Gemini 标注，这既是它的成本来源，也是它无法被本 skill 吸收的部分。

### 建议做法

1. **新增 L4 叙事层，做成文体层开关**
   与 L1.5 同构：新增 `narrative` 开关（或复用 `banlist` 语义扩展），默认关闭，仅在长文本/多章场景启用。避免污染通用 profile 的轻量定位。

2. **复用现有基线校准机制**
   `--calibrate`（均值 ±2σ）原封不动即可用于 L4 指标——这**恰好是正确姿势**：论文阈值（英文 / Books3 / 5,000 词）对中文网文零迁移性，必须由自有语料校准。

3. **报告新增两节**
   - `## L4 叙事层`：L4-A/B/C/D 的命中表
   - `## 结构层修改建议`：把 StoryScope 的 30 个核心特征翻译成中文网文的**改写动作清单**

4. **SKILL.md 增加能力边界声明**
   明确写清"本检测覆盖文笔层；文笔层的改写不改变叙事结构"。把边界从缺陷变成**诚实的卖点**，并指向叙事层人工核查清单。

## 六、最大的价值不在"再加规则"，而在补一个产品缺口

论文对本 skill 最有价值的贡献，是暴露了一个**定位缺口**：

> 现在只能回答"这段文字**写得多像** AI 的节奏与模板"，
> 完全无法回答"这个故事**讲得多像** AI 的故事"。

而论文用数据证明了三件事：
1. 文笔层最容易被绕过（模型迭代 + 表层改写）
2. 叙事层更耐久（改它需要结构性重写）
3. **在词句层努力是无效的**——这是对"去 AI 味"这一用户目标最重要的提醒

因此建议把 30 个核心特征（论文 Table 16）翻译成一份**中文网文的叙事层改写清单**，直接放进 skill：
- 降低篇末点题（少写"命运终究……"）
- 引入支线与时间跳跃（不要单线顺叙）
- 减少身体化情绪堆砌，按语体决定是否直写情绪
- 增加具名互文与读者介入
- 避免"主角选择驱动一切"的整洁因果

这份清单的**实用价值高于再加 5 个统计指标**，因为它是可执行的修改动作，而 flags 只是报警。

> **补充（见 §一·补）**：这份清单的正确落点其实是**大纲层**，不是正文层。要在成稿里删掉"点题段"，就得先重写结构；但要在章纲里不规划"点题段"，只需改一行。同一份清单放在大纲层使用，改动成本下降一个数量级。

## 七、数值迁移性速查（为什么不能照搬论文阈值）

| 论文设置 | 本 skill 场景 | 影响 |
| --- | --- | --- |
| 英文 | 中文 | 时间锚点、互文标记、语气词规则全部不同 |
| Books3 文学短篇 | 中文网文 | 语体差异极大（论文的"人类特征"可能是网文的"AI 特征"） |
| ~5,000 词整篇 | 单章 3,000–5,000 字 | 时间线 / 支线类指标在单章上不可测 |
| 已出版编辑稿 vs 一次性初稿 | 人机协作文本（作者改过） | **论文完全未测此场景**，是最需要自行校准的部分 |
| 5 个 2026 年模型 | 未知/多模型 | 指纹特征无迁移性 |

> 论文自身的局限（标注者 Gemini 自偏好偏差、人-人 κ=0.74、人类样本为已出版编辑稿、未测结构性对抗攻击）进一步说明：**它的 30 个核心特征应作为"方向参照"，不应作为"金标准规则表"。**

## 八、建议的推进顺序（2026-09-15 修正）

| 选项 | 内容 | 价值 / 成本 |
| --- | --- | --- |
| **A** 先验证 | 跑情绪直写对照实验（AI 章节 vs 人类章节的 `EMO_PAT` 命中率），确认现有规则是否需要修正 | **最高性价比**：成本最低、信息量最大，且可能发现规则错误 |
| **B** 边界声明 | SKILL.md 加**四层**能力边界声明（文笔层已覆盖 / 大纲层与叙事层未覆盖），不动代码 | 低成本，立刻消除"虚假改善感"缺陷 |
| **C′** 大纲层检测 ← **修正后的首选扩展** | 实现 L4-大纲：多线并发度 / POV 集中度 / 场景密度同构 / 情绪节拍幅度 / 伏笔并发与跨度，**纯规则** | **高价值**：不破定位、改动成本低、位于成因上游（预防优于事后） |
| **D′** 叙事层近似 | L4-B 篇末点题 + L4-C 读者介入（单章有效）；L4-A 时间线 + L4-D 互文（需多章聚合） | 中等成本，作为大纲层的补充证据 |
| **E** 真叙事层（需 LLM） | StoryScope 式语义特征抽取 | **不建议**：成本高、破坏"不靠 LLM"定位，且论文自身存在标注偏差风险 |

**推荐顺序：A → B → C′ → D′**（E 建议长期不做）。

> 与上一版的差异：上一版把 C（叙事层近似）当首选扩展，现在降为 D′；新增的 C′（大纲层）取代其首选位置。原因是叙事层近似同时踩了"难做"与"难改"两个坑，而大纲层两者皆优。

## 附：向量密度路线已被实测否定（2026-09-15）

曾评估"把正文转向量、用跨章向量密度识别 AI 味"作为语义场层的实现路径。
**实测结论：不可行，语义相似度高 ≠ AI 味。**

- 表面区分力（A vs C）d = +0.82~+1.00 全方向正确，但属假象；
- 密度 × 章号 r = +0.47~0.50，控制位置后与 flag 的相关性全部塌掉（p>0.1）；
- 决定性的命中率检验：短语云已确认的 18 个装置复用章对，AUC = 0.43~0.46（<0.5），向量抓不到。

详见 `vector-density-feasibility-test.md`。
**语义场层的实现路径仍应为「跨章短语云」（字面精确匹配），而非语义向量（模糊匹配）。**
